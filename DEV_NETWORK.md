# Настройка локальной сети для разработки Flux

Этот документ описывает, как настроить локальную сеть для тестирования и разработки Flux с разных устройств (MacBook, Windows) в одной Wi-Fi или проводной сети.

---

## 1. Запуск сервера в локальной сети

По умолчанию серверы разработки (например, Vite, Node.js или бэкенд на Rust/Go) запускаются на `localhost` (127.0.0.1) и недоступны с других устройств в сети. Чтобы сделать их доступными, необходимо привязать сервер к адресу `0.0.0.0`.

### Для фронтенда (Vite)
Запустите сервер с флагом `--host`:
```bash
# Использование npm
npm run dev -- --host

# Использование yarn
yarn dev --host
```
В терминале вы увидите два адреса:
- `Local`: http://localhost:5173/
- `Network`: http://<ВАШ_IP_АДРЕС>:5173/ (Используйте этот адрес для других устройств)

### Для бэкенда
Убедитесь, что ваш сервер слушает хост `0.0.0.0`, а не `127.0.0.1` или `localhost`.
- **Node.js (Express):** `app.listen(PORT, '0.0.0.0')`
- **Rust (Actix/Axum):** `HttpServer::new(...).bind("0.0.0.0:8080")`
- **Go:** `http.ListenAndServe("0.0.0.0:8080", nil)`

---

## 2. Настройка IP-адресов

Для подключения к серверу вам необходимо узнать IP-адрес устройства-хоста (на котором запущен сервер) в вашей локальной сети. Обычно он выглядит как `192.168.x.x` или `10.0.x.x`.

### Как узнать IP-адрес на macOS (MacBook):
1. Откройте **Терминал**.
2. Введите команду:
   ```bash
   ipconfig getifaddr en0
   ```
   *(Если вы подключены по кабелю или используете другой интерфейс, попробуйте `en1` вместо `en0`)*.
3. Полученный адрес (например, `192.168.1.15`) — это IP-адрес вашего Mac.

### Как узнать IP-адрес на Windows:
1. Откройте **Командную строку** (`cmd`) или **PowerShell**.
2. Введите команду:
   ```cmd
   ipconfig
   ```
3. Найдите раздел, соответствующий вашему подключению (например, "Адаптер беспроводной локальной сети Wi-Fi").
4. Ваш IP-адрес указан в строке **IPv4-адрес** (например, `192.168.1.20`).

---

## 3. Настройка портов

Чтобы устройства могли обмениваться данными, порты, которые использует сервер, должны быть открыты в брандмауэре (файрволе).

**Стандартные порты для Flux:**
- **Фронтенд:** `5173` (по умолчанию для Vite)
- **Бэкенд / API:** Уточните используемый порт (например, `3000` или `8080`)

### Открытие портов в Windows (если сервер запущен на Windows):
1. При первом запуске сервера Windows обычно показывает окно "Брандмауэр Защитника Windows". Нажмите **"Разрешить доступ"** (желательно для частных сетей).
2. Если окно не появилось:
   - Откройте "Монитор брандмауэра Защитника Windows в режиме повышенной безопасности".
   - Перейдите в "Правила для входящих подключений" -> "Создать правило...".
   - Выберите "Для порта", протокол "TCP", укажите нужный порт (например, 5173).
   - Разрешите подключение.

### Открытие портов на macOS:
Обычно macOS не блокирует входящие соединения для запущенных процессов разработчика, если брандмауэр не настроен на строгий режим.
- Если соединения не проходят, проверьте настройки: **Системные настройки** -> **Сеть** -> **Брандмауэр**, и убедитесь, что приложению/терминалу разрешены входящие подключения.

---

## 4. Подключение с MacBook

Если сервер запущен на Windows (или другом устройстве):
1. Узнайте IP-адрес Windows-машины (см. пункт 2). Например: `192.168.1.20`.
2. На MacBook откройте браузер.
3. Введите адрес в формате: `http://<IP_СЕРВЕРА>:<ПОРТ>`
   - Пример для фронтенда: `http://192.168.1.20:5173`
   - Пример для бэкенда: `http://192.168.1.20:8080`

Если сервер запущен на самом MacBook, вы можете обращаться к нему через `http://localhost:<ПОРТ>`.

---

## 5. Подключение с Windows

Если сервер запущен на MacBook (или другом устройстве):
1. Узнайте IP-адрес MacBook (см. пункт 2). Например: `192.168.1.15`.
2. На Windows откройте браузер.
3. Введите адрес в формате: `http://<IP_СЕРВЕРА>:<ПОРТ>`
   - Пример для фронтенда: `http://192.168.1.15:5173`
   - Пример для бэкенда: `http://192.168.1.15:8080`

---

## 6. Решение возможных проблем

- **Сайт не открывается / Превышено время ожидания:**
  - Убедитесь, что оба устройства подключены к **одной и той же Wi-Fi сети**.
  - Проверьте, не блокирует ли антивирус или брандмауэр (Firewall) соединения на сервере.
  - Убедитесь, что сервер был запущен с привязкой к `0.0.0.0` (например, `vite --host`).
- **Смена IP-адреса:** Роутеры могут назначать устройствам новые IP-адреса при переподключении. Если вчера всё работало, а сегодня нет, проверьте IP-адрес заново.
- **VPN:** Если на одном из устройств включен VPN, он может маршрутизировать локальный трафик мимо вашей сети. Попробуйте отключить VPN для тестирования.
